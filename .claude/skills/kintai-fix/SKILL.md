# kintai-fix — 勤怠修正ワークフロー

目的: 「定時前は丸めてほしい」→「定時以降も丸めてしまった」型の事故を防ぐ。
修正指示は暗黙の適用範囲・例外条件を含む。**コードを読む前・書く前に仕様を確定させる。**

## 手順

### 1. 必読資料

`docs/DOMAIN_MAP.md` を読む（全文・短い）。必要な節だけ `docs/DOMAIN_REFERENCE.md` を追加参照。
**このステップの省略禁止。** コードから仕様を推測しない。

### 2. 適用範囲マトリクスを埋める

指示文から以下を埋める。**指示文に明示がなく DOMAIN_MAP からも確定できない項目は、推測せずユーザーに質問する。**

- 対象打刻: 出勤 / 退勤 / 両方（丸め・計算は出退勤で非対称が既定）
- 申請条件: 申請の有無・種類で挙動が変わるか（早出申請・残業申請は丸めを無効化する）
- 雇用形態: full / part / 両方（休憩控除・残業基準が異なる）
- 期間基準: 締め期間（既定）/ 暦月 — 「今月」「月次」は締め期間と解釈するのが原則
- 反映先: DB保存値 / 表示のみ / 両方（保存と表示で計算タイミングが分離している）
- 対象画面: 打刻 / records / 承認 / 一覧 / Excel / ホーム — 同種ロジックが複数箇所に重複している前提で影響先を列挙
- 対象ユーザー範囲: 全員 / 役割 / 部署 / 雇用形態（除外基準は部署名 `["管理者","管理職"]` が正）

### 3. before/after 具体例で合意

修正後の挙動を**境界値を含む具体例3つ以上**でユーザーに提示し、合意を得てから実装に進む。
必須の例: (a) 指示の典型ケース (b) 境界値（定時ちょうど・締め日当日・14分/15分など） (c) **変わらないべきケース**（今回の修正が及んではいけない側）。

例（「定時前の出勤は定時に丸める」の場合）:
- 始業8:30・8:10打刻 → 8:30 記録（丸める）
- 始業8:30・8:30打刻 → 8:30 記録（境界）
- 始業8:30・8:45打刻 → 8:45 記録（**定時後は丸めない**）
- 早出申請ありで8:10打刻 → 8:10 記録（**申請時は丸めない**）

### 4. 実装

- 修正対象ファイルは DOMAIN_MAP のファイルマップから特定。grep で同種ロジックの重複箇所を必ず確認（片方だけの修正禁止）
- 日付範囲の新規実装は `lib/closing.ts` を使う。暦月ベタ書き禁止
- JST 日付基準は「+9h→日付部品→−9h」。`getUTCDate()` 先行禁止

### 5. 検証

- 手順3の具体例すべてをコード上でトレース（または実行）して確認
- `npx tsc --noEmit` で型チェック

### 6. ドキュメント更新

- `docs/STATUS.md` の変更履歴に追記
- 仕様が変わった場合 `docs/DOMAIN_MAP.md` / `DOMAIN_REFERENCE.md` の該当箇所を更新
- ISSUE.md 由来の修正なら該当行を処理（STATUS へ昇格済みか確認）
