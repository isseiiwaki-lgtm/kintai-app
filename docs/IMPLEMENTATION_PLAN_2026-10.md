## 0. 全作業に共通する決まり

実装中に迷ったら、まずここに戻る。

1. **打刻時刻は3層**。計算は必ず②で行う
   - ①実打刻 `rawClockIn/Out`：ボタンを押した瞬間の値。**証跡専用。計算に使わない**
   - ②記録時刻 `clockIn/Out`：丸め・上限・修正を反映した値。勤務時間・遅刻・早退・残業はすべてこれが基準
   - ③修正前値 `originalClockIn/Out`：初回修正時に退避した②
2. **事実でしか変わらない値を既定値で推定しない**。例外が起きたら入力を求め、無ければアラート
3. **ある計算結果を、別の新しい値の根拠にしない**（「不足時間」「休憩超過」などの新しい値を作らない）
4. **遡及しない**。スイッチ・計算式の変更は、変更後の打刻・承認にだけ効く。過去の月・締め済み（LOCKED）のデータは書き換えない
5. **日付は「UTC 0時＝その日」で保存**。人間は日本時間の日付で考えているので、入力時に変換、表示時に戻す。`new Date(y, m-1, d)` で保存しない
6. **一般社員の画面に、削った時間などの内訳を出さない**。内訳は管理画面と Excel だけ
7. 同じロジックが複数ファイルに重複している前提で、grep で全箇所を確認してから直す（片方だけ直すのは禁止）
8. 作業ごとに `npx tsc --noEmit` と `npm run test` を通す。各作業の「具体例」は vitest のテストケースにする

### I. 休憩の記録を申請に一本化

- **対象**：`config/attendance.config.ts`・`lib/attendance.ts`（休憩・所定・実働の計算）、`app/(app)/clock/*`、申請（`requests/new`・`requests/actions.ts`・`admin/requests/actions.ts`）、ユーザー管理、`api/admin/anomaly-check`、承認詳細・`/records`
- **休憩分数の決め方を1つの関数にまとめる**（例：`resolveBreakMinutes`）

  2. 値が無い
     - 半休の日 → 0
     - パート → 0（後述のアラート対象になる場合あり）
     - 社員 → 規定値：`User.breakMinutes`、無ければ会社設定「休憩時間控除ルール」（`Setting.break1*/break2*`）を**定時の拘束時間**に当てた値
  - 審査中の休憩申請は差し引かない（承認された時点で反映）
- **会社設定の休憩ルールを計算に接続**：今は設定画面で保存できるのに、計算はハードコードの `BREAK_RULES` を使っていて設定が効いていない。`calcLegalBreak` の呼び出し元すべてを置き換える。grep で確認した呼び出し元：`clock/actions.ts`、`admin/approval/[userId]/actions.ts`（3か所）、`admin/requests/actions.ts`（2か所）、`api/admin/export-xlsx/route.ts`、`api/admin/recalculate/route.ts`、`lib/attendance.ts`（2か所）
- **所定の労働時間** ＝ 拘束時間（定時の終業−始業）− 所定休憩（`User.breakMinutes` か会社設定）。`calcScheduledMinutes` を直す。**影響**：半休の時間（所定の半分）も変わる（野木さん 360→300分 なら半休 150分）
- **打刻画面**
  - 共通：[出勤][退勤][外出]（外出は押すと[戻り]に切り替わる）
  - パートだけ：休憩時間 [0][15][30][45][60]。**押した値がその日の休憩の合計（上書き）**。選んだ値を色で示す。承認は不要。案内文は「その日の休憩がすべて終わってから押す」
  - 休憩開始・終了ボタンは廃止。過去の休憩打刻データは消さない
- **休憩申請（BREAK）**：60分超・押し忘れ用。分数（15分刻み）を入力。承認されたら `AttendanceRecord.breakMinutes` に入れて勤務時間を計算し直す。承認待ちの間は承認詳細に「承認待ちの休憩申請あり」と出す
- **ユーザー管理**：所定休憩（分・任意）の入力欄を追加
- **パートの休憩申請漏れアラート**（条件はどちらか）：①所定休憩が設定されているのに休憩の記録が無い ②実働が6時間を超えたのに休憩の記録が無い。`anomaly-check` の「6時間超」だけの条件もこれに合わせる
- **具体例**
  - 野木さん（パート・9:00–15:00・所定休憩60）：[60] を押す → 実働300・所定300／押し忘れ → 実働360・アラート
  - パート・所定休憩なし・5時間勤務・記録なし → 0分・アラートなし
  - パート・7時間勤務・記録なし → 0分・アラート
  - 社員・9:00–18:00・記録なし・所定休憩未設定 → 会社設定から60分
  - 社員・9:00–17:00・所定休憩60を設定 → 60分（未設定なら会社設定で45分になる）
  - 社員・休憩申請0分が承認済み → 0分
  - 社員・午前半休 → 0分

### J. 遅刻・早退の定義（確認だけ）

- 時刻の差だけで出す（今の `calcMetrics` のまま）。「働いた時間の不足」で出す案は撤回済み。新しい値を作らない
- 旧勤怠Reco は 12:05 早退（定時 15:00）を「早 2:00」と出していたが、新システムでは 3:00 になる（熊谷さん了承済み）

### L. 承認経路：同じステップに複数の承認者（いずれか1名）
