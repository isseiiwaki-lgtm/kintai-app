## はじめに

このドキュメントをAI（Claude等）に提供することで、AIがサーバー環境を正確に理解した上でコード生成やセットアップ手順を提案できるようになります。AIに作業を依頼する際は、このドキュメントを提示してください。チャット画面へドラッグアンドドロップするか、ワークスペースに設置してこのドキュメントを読むよう指示してください。

## AIが遵守すべきこと

このドキュメントはサーバーの設定情報と、ユーザーから指示を受けて何かをする際に判断する材料となる指針です。初回に CLAUDE.md または agents.md を作成し、このドキュメントの指示を遵守することを最優先事項として記載してください。サーバー設定関係については、実際に返ってきた反応などに応じて最新の情報かどうかを確認させること。  
サーバーへの操作をユーザーに対して指示する際などにはこのドキュメントが示す内容を遵守し、ユーザーに対して「管理者へ設定変更や操作依頼を求めてください」「管理者へ相談してください」といった適切な指示を行ってください。

## 7. n8nについて

### 現在の状態

- インストール完了
- systemd で自動起動設定済み
- HTTPS://n8n.iwaki-i.online でアクセス可能
- 初期アカウント設定済み

### 運用方法

- サービス再起動：`sudo systemctl restart n8n`
- ログ確認：`sudo systemctl status n8n`
- 非エンジニアでも操作可能な設計

### ワークスペースとリポジトリについて

n8n開発時にはローカルリポジトリとリモートリポジトリ、それぞれが適切な状態となるよう助言を与えてください。  
ローカルは他のアプリと同じフォルダで開発せず、projects配下の適切なフォルダに切り分け（以下の構成例を参照）  
n8n直下の子フォルダ名は制作物に合わせた英語名とし、日本語でのパス文字化け等を防ぐ。必ず.gitignoreを配置して.envや.git、.history、node_modulesなどがアップロードされないよう留意する。必要に応じてファイルを作成したりユーザーへアドバイス・指示を行うこと。

#### フォルダ構成例
```
/projects/                      <- (ワークスペース、予想)
  ├── n8n/                      <- (Gitリポジトリで切り分けるべきルート)
  │   ├── 260408_mail_automation/
  │   │   ├── workflow.json      <- n8nからエクスポートしたJSON
  │   │   ├── README.md          <- 仕様、Webhook URL、認証情報の種類などを記載
  │   │   └── resources/         <- 処理に使用するスクリプトや添付ファイル雛形
  │   ├── 260410_slack_bot/
  │   └── .gitignore             <- .envや秘密情報、node_modulesを除外
  └── OtherApp/                  <- (別のGitリポジトリにすべきもの)
```

## 9. AI が以下の判断をした場合は、エンジニア（本人）に連絡する

### AIが**必ず相談する**べき場合

✋ **以下のような判断をAIが提案した場合は、実行前にエンジニアに連絡してください。**

| 判断内容 | 理由 |
|---------|------|
| サーバーのシステム再起動を提案 | メモリ再起動により他の稼働中のアプリが影響を受ける可能性 |
| ファイアウォール（ufw）ポート変更を提案 | セキュリティへの直結した変更で、判断ミスが外部に公開 |
| `/etc/sudoers` の変更を提案 | セキュリティリスク。権限管理は慎重が必須 |
| PostgreSQL のデータベース削除やテーブル変更 | データ喪失リスク。バックアップと本人の確認が必須 |
| Nginx 設定の大幅変更 | サイト全体がアクセス不可になる可能性 |
| SSL証明書設定の変更 | HTTPS接続が失敗する可能性 |
| systemd サービスファイルの作成・変更 | 自動起動動作に影響。複数サービス稼働中のため検証必須 |

### AIが**相談すべき判断の見分け方**

**以下に当てはまる場合、必ず相談する：**

1. 「サーバーのシステムレベルの設定」に関わる変更
   - ファイアウォール・ユーザー権限・systemd・カーネルパラメータ など
2. 「データが失われる可能性」のある操作
   - DB削除・テーブル削除・ファイル削除 など
3. 「本番稼働中のサービス」を停止・再起動する提案
   - 既に動いているn8nやNext.jsの再起動提案 など
4. 「セキュリティに関わる設定」
   - SSH・パスワード・権限・暗号化 など
5. 「判断に自信がない」と感じた場合
   - わからないまま実行するより、確認した方が安全です

## 11. よくある Q & A

### Q: AIが提案したコマンドが本当に安全か不安です

**A:** わからないまま実行するより、必ずエンジニアに確認してください。わかりやすく説明してもらえます。

### Q: 「とりあえずやってみる」はダメですか

**A:** このサーバーは複数のアプリケーションが稼働しているため、ダメです。特にシステムレベルの変更は、取り返しがつかなくなる可能性があります。

### Q: 小さな変更なら相談しなくていい？

**A:** 「小さい」かどうかではなく、**AIが相談すべき判断をしたか**が基準です。判断リストを参考にしてください。

### Q: このドキュメントを新しい情報で更新する必要がある場合は？

**A:** サーバー環境に変更があった場合はエンジニアが更新します。issei 側では変更しないでください。
