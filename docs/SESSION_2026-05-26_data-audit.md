## 作業1: 実データの問題確認と修正

### 対象ファイル

### 実データのカラム（現行 CSV 出力）


### 判明している問題点

#### 問題A: `workingMinutes` が空/0 のレコード
退勤時刻があるにもかかわらず勤務時間が空または0になっているケース:

| 氏名 | 日付 | 退勤時刻 | 勤務時間(分) |
|------|------|----------|------------|
| 小林匠 | 5/07 | 17:45 | (空) |
| 小林匠 | 5/08 | 17:36 | 0 |
| 熊谷和樹 | 5/07 | 19:15 | (空) |
| 須田育美 | 5/07 | 16:01 | 0 |
| 須田育美 | 5/11 | 16:00 | (空) |
| 根本桜子 | 5/12 | 16:00 | (空) |

**推定原因**: 試験運用初期（4月末〜5月初）は `workingMinutes` の自動計算ロジックが未実装または不完全だった。DBには生打刻はあるが `workingMinutes` がセットされていない。

**確認コマンド（VPS上で実行）**:
```sql
SELECT u.name, ar.date, ar."clockIn", ar."clockOut", ar."workingMinutes"
FROM "AttendanceRecord" ar
JOIN "User" u ON u.id = ar."userId"
WHERE ar."workingMinutes" IS NULL AND ar."clockOut" IS NOT NULL
ORDER BY u.name, ar.date;
```

**修正方針**: 退勤時刻と出勤時刻の差から `workingMinutes` を再計算して UPDATE。
ただし休憩控除ルール（Setting テーブル）を適用する必要あり。

#### 問題B: パートの「残業時間」が全勤務時間と同値
```
岡田友美(パート) 5/01: 勤務203分, 残業203分 ← おかしい
石井章子(パート) 5/01: 勤務371分, 残業371分 ← おかしい
```

**根本原因（コード確認済み）**: `app/api/admin/export/route.ts:60`
```ts
const scheduled = u.employmentType === "full" ? 480 : 0
// パートは所定=0 → overtime = workingMinutes - 0 = 全勤務時間
const overtime  = Math.max(0, (r.workingMinutes ?? 0) - scheduled)
```
パートの所定時間を **0分固定** としているため、全勤務時間が残業扱いになる。

**修正選択肢（ユーザーに確認要）**:
- A) パートは `overtime = ""` (空欄) — 残業の概念なし扱い
- B) パートも `workStartTime`〜`workEndTime` の差を所定時間として計算
- C) パートは `workEndTime` が NULL なら空欄、設定あればそこから計算

**確認コマンド（VPS上で実行）**:
```sql
SELECT u.name, u."employmentType", u."workStartTime", u."workEndTime"
FROM "User" u
WHERE u."employmentType" = 'part'
ORDER BY u.name;
```

#### 問題C: 退勤未打刻レコード（本日打刻中）
5/26の退勤なしレコードは当日打刻中なので正常。CSV 出力時に除外するか注記を入れる。
