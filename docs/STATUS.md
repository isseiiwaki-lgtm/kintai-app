## 実装済み基本仕様（動作確認済み）

### 一般ユーザー機能
- **ホーム** `/` — 今日の打刻状態・出退勤時刻・勤務時間、今月の実績（出勤日数・合計時間）。インフォメーションセクション（退勤漏れ・却下申請・要確認・審査中）
- **打刻** `/clock` — 出勤・退勤・外出・戻り・休憩開始/終了。2×2グリッドUI。開発用デバッグパネルあり
- **勤怠記録** `/records` — 月次一覧（日付/曜日/出退勤/残業/状態バッジ）、前後月ナビ、修正依頼リンク。締め日連動集計期間
- **申請** `/requests` — 申請一覧・取り下げ機能
- **申請 新規** `/requests/new` — 残業申請/遅刻早退/欠勤/休暇申請（有給・代休・半日）/打刻修正/その他
- **マニュアル** `/manual` — `content/manual-user.md` をレンダリング

### 管理者機能 (ADMIN/APPROVER)
- **勤務状況一覧** `/admin/attendance` — 全ユーザー月次一覧、前後月ナビ、締め日連動
- **勤怠承認** `/admin/approval` — ユーザー別ステータス集計。個人詳細（`/admin/approval/[userId]`）: 月次一覧・編集モーダル・一括承認・一括締め
- **申請承認** `/admin/requests` — 申請一覧・承認/却下・修正・削除。審査中は全件表示・処理済みは月別切替
- **休日カレンダー** `/admin/holidays` — 祝日一括シード、手動追加・削除
- **ユーザー管理** `/admin/users` — 一覧（従業員コード順）・新規作成・編集・削除・複製、CSVインポート/エクスポート、両メール表示
- **設定** `/admin/settings` — 締め日・休憩控除ルール設定
- **変更履歴** `/admin/changelog` — 月別打刻変更ログ

### 認証

- 未登録Googleアカウント → `/link` で会社メールと紐付け

## P2 タスク（メイン機能実装）

### ステータス刷新（最優先）
- [ ] **「未確認」廃止 → 「打刻済」「要確認」へ** — 現行 OPEN = 未確認を廃止。打刻がある = 「打刻済」。打刻漏れ・遅刻等の可能性あり = 赤「要確認」表示。管理者締め後は「締め済」。影響: ホーム・`/records`・`/admin/attendance`・`/admin/approval` 全域

### 表示項目整理
- [ ] **`/records` 表示項目** — 出勤・退勤・労働時間・休憩・中抜け・所定・残業・深夜・遅刻・早退・欠勤
- [ ] **`/admin/attendance` 表示項目** — 総勤務時間・所定・残業・未承認・承認済。`/admin/approval` 詳細も同様に整理

### 残業・勤怠計算改善
- [ ] **パート残業計算（法定ベース）** — 法定労働時間（1日8h・週40h）超えで×1.25。所定〜法定内は通常時給。深夜（22〜5時）×1.25。月60h超×1.5。見かけ上の表示はフルタイムと同様（所定・残業を表示）

### 未完了
- [ ] **既存 COMMENT タイプは存続** — CORRECTION と別に残す（テキストのみの連絡用途）

## P3 タスク（後続）

### 設定機能追加
- [ ] **設定: 定時前打刻→定時扱いスイッチ** — 例: 9時出社の人が8:40打刻→9:00扱い
- [ ] **設定: 定時±14分以内→定時きっかりスイッチ** — 例: 17時の人が17:13打刻→17:00扱い
- [ ] **設定: 時刻丸め処理** — 適法ルール: 日次は1分毎カウント・切り上げのみ可。月次合計は30分単位（31〜59分は切り上げ）

### 大規模機能
- [ ] **多段階承認** — 管理項目に「承認経路」追加。所属部署ごとに承認者順序設定。飛び越し承認ボタン実装。最後の承認者=「決裁者」。決裁者承認で完全承認完了
- [ ] **xlsx出力** — 「個人別日別勤務報告書」形式。実現可否含め検討
- [ ] **メール通知** — 優先度: 承認依頼通知 > 打刻漏れ（管理者向け） > 却下通知 > 承認完了通知。`companyEmail` 優先・なければ `email` にフォールバック
- [ ] **申請データ削除時「削除済」表示** — 管理側削除後もユーザー側に申請記録を残す。ステータス「承認済」→「削除済」

## 懸念事項

- **パート曜日ごと定時設定** — 優先度最低。同一人物でも曜日により所定終業が異なるケースに対応。DBカラム増加を許容できる段階で実装検討
- **打刻の時刻丸め** — 現在は生時刻を保存。会社の丸めルール（例: 15分単位）が必要か要確認
- **勤務時間計算** — workingMinutes の更新タイミングと外出/休憩控除のロジックを要確認
- [ ] **LeaveBalance テーブル** — migration 済みか未確認。actionDeleteUser で `.catch(()=>{})` で握り潰している
- [ ] **外出・休憩の複数回問題（要仕様確認）** — 現在 `goOutAt/returnAt`・`breakStart/breakEnd` は各1ペアのみ保持。2回目で上書き消滅。対応方針:
  - A) 現行のまま（1日1回外出を前提とし、複数回は修正依頼で対応）
  - B) スキーマに `GoOutLog[]` テーブルを追加して複数回対応
- **出勤日判定の優先順位** — 休暇申請承認済 > 休日カレンダー > 個人所定出勤曜日設定（休日に休暇申請不可などのバリデーションで矛盾を事前排除）
- **AttendanceRecord 原打刻と変更打刻の分離** — 管理者編集時に元の打刻記録を保持するかどうか設計要検討
