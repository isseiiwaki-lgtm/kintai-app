## 2. 現状の構成と注意点

| 項目 | 状態 |
|---|---|
| セキュリティ更新（noble-security） | unattended-upgrades で自動適用 |
| 通常更新（noble-updates） | **自動対象外** → 手動 |
| Docker（download.docker.com） | **自動対象外** → 手動。更新時にコンテナが再起動する |
| Node.js（nodesource node_20.x、導入時 v20.20.2） | **自動対象外** → 手動。Node 20 はサポート終了済みのため 22 以降への移行を検討。勤怠アプリ・n8n・PM2 がすべてこの Node で動く |
| PostgreSQL 16（apt） | セキュリティ更新は自動適用。適用時に DB が再起動し、アプリが一瞬つながらなくなることがある |
| n8n（`npm install -g`、導入時 v2.8.4） | **apt の対象外** → 手動（`npm` で更新）。n8n.iwaki-i.online で外部公開中。通知は未接続で、現状ほぼ使っていない |
| PM2（`npm install -g`） | **apt の対象外** → 手動。自動起動は systemd ユニット `pm2-ubuntu` が担当 |

| Docker のコンテナ | 中身は未確認（ubuntu ユーザーに docker 権限がない。2026-11-12 調査）。使っていなければ Docker ごと削除も検討 |
| cloud-init | hold 中（VPS業者の設定と思われる。触らない）。更新されずに1件残るのが正常 |
| 未適用の更新 | 2026-11-20 時点で 38 件（通常更新・Docker・Node など） |

## 3. 定期作業手順（目安：月1回＋重大脆弱性の報道時）

```bash
# 1) 更新の確認
sudo apt update
apt list --upgradable

# 2) DB のバックアップ（パスワードは ~/.pgpass に保存済み）
pg_dump -h 127.0.0.1 -U ippcdb db_kintai > ~/backup_$(date +%Y%m%d).sql

# 3) 適用（業務時間外に。needrestart がサービスを再起動するため、アプリ・n8n・Docker のコンテナが一時停止する）
#    前回（2026-10-06）と同じく full-upgrade を使う（upgrade だとカーネル等が保留されることがある）
sudo apt full-upgrade
sudo apt autoremove

# 4) 再起動が必要か確認（カーネル更新など）
ls /var/run/reboot-required && cat /var/run/reboot-required.pkgs

# 5) 必要なら再起動
sudo reboot

# 6) サービスの稼働確認
systemctl status nginx postgresql n8n pm2-ubuntu
systemctl status kintai.service          # disabled / inactive のままか（過去に再起動でポート3000を奪った）
pm2 status                               # kintai が online か（sudo を付けない。ubuntu ユーザーで見る）
curl -sI https://kintai.iwaki-i.online | head -1
sudo docker ps
```

- n8n・PM2 は apt では更新されない。`npm outdated -g` で確認し、更新する場合は n8n のリリースノートを読んでから行う。

## 4. 個別の脆弱性に対応したかの確認方法

```bash
apt policy nginx                         # Installed と Candidate が一致しているか
apt changelog nginx | head -40           # 対象のCVE番号が含まれているか
systemctl status nginx                   # 起動時刻が更新より後か（再起動されているか）
```

- 修正がまだ配布されていない場合は、Ubuntu CVE トラッカー（https://ubuntu.com/security/cves）で CVE 番号を検索して状況を確認する。
- 配布を待つ間は、関連する機能（例：HTTP/2・HTTP/3）を一時的に無効にしてリスクを下げることを検討する。

## 5. 自動更新の確認コマンド

```bash
cat /etc/apt/apt.conf.d/20auto-upgrades            # 2行とも "1" になっているか
sudo unattended-upgrade --dry-run --debug          # 動作テスト
less /var/log/unattended-upgrades/unattended-upgrades.log   # 実行履歴
grep restart /etc/needrestart/needrestart.conf     # サービスの自動再起動設定
```

- dry-run ログ冒頭の「Not running on the development release.」は正常なメッセージ。
- OS の自動再起動（`Automatic-Reboot`）は **無効のまま**（稼働状況を見て手動で再起動する方針）。
