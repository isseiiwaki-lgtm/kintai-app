## 4. 休憩・所定・実働ロジックの再設計（議論中）

### 現行コードの問題（`lib/attendance.ts`・`config/attendance.config.ts`）

- `employmentType` で分岐しているのは本来「休憩の**記録方法**」の違いなのに、「控除**ルール**」の違いとして実装されている
- `calcScheduledMinutes` は雇用形態を問わず法定休憩で所定を出す → 野木さん（拘束360分）は所定360分になるが正しくは300分
- `calcLegalBreak` の閾値判定が休憩控除前の在席時間（在席481〜540分で60分控除＝過大控除の疑い）
- 外出と法定休憩の二重控除の可能性
- `anomaly-check` のパート休憩漏れ検知が6時間超のみ
- **休憩時間控除ルールの設定が計算に反映されていない（死蔵）** — 会社設定画面に「休憩時間控除ルール」（`Setting.break1Threshold/break1Minutes/break2Threshold/break2Minutes`）があり保存もできるが、参照は `admin/settings` の画面と保存処理のみ。実際の計算（打刻・承認時の編集・申請承認・Excel・一括再計算・`lib/attendance.ts`）はすべて `config/attendance.config.ts` のハードコード `BREAK_RULES`（`calcLegalBreak`）を使う。**画面で値を変えても計算は変わらない**。当初「設定画面化が必要」と記載したのは誤りで、必要なのは既存設定を計算に接続すること（2026-09-16 ユーザー指摘で訂正）。`workSun〜workSat` と同じ「設定の死蔵」パターン

### 合意した原則

> **事実でしか変わらない値を既定値（Default）で判定しない。例外が起きたら例外に合った入力を求め、入力がなければアラートを出す。**
> **計算は実態（打刻）ベース。法定との乖離は記録を書き換えず警告で出す。**

- 昼休憩の時刻（12:00）を控除判定に**使わない**。「昼を含んだから控除」ではなく「休憩をとったから控除」
- 休憩の外出打刻は運用で合理化済み。休憩時間帯への外出打刻の例外はカバー不要

### 合意した設定モデル

- `workStartTime/workEndTime` ＝ 規定出勤・退勤（拘束時間）。既存のまま
- `User` に**任意**の規定休憩分数を追加。未記入なら「拘束時間 × 会社設定『休憩時間控除ルール』（既存 `Setting.break1*/break2*`）」の既定値
- 所定労働時間 ＝ 拘束 − 休憩（導出値）
- 例：熊谷さん 9:00–18:00 → 既定60分・所定480分／9:00–17:00 の方 → **要記入60分**・所定420分／**野木さん 9:00–15:00 → 要記入60分（無給）・所定300分**

### 合意した休憩控除の判定順

1. 休憩打刻あり → 実時間を控除（社員・パート共通。社員は短縮/延長の実態）
2. 休憩打刻なし
   - 半休申請あり → 0（半休は必ず午前/午後単位＝法定休憩0。残業で休憩を取ったなら打刻が必須）
   - 遅刻早退申請あり → 申請に「休憩0」チェックボックス（新設）ONなら0、OFFなら規定値
   - パート → 0 ＋ 休憩打刻漏れ確認アラート（休憩打刻漏れの修正申請は現状無し・要検討）
   - 社員・申請なし → 規定値

### 保留・次回確認

- **遅刻の申請なし日（実データ精査が必要）**：野﨑さんは**パート**。パートの遅刻は単純な労働時間減で問題ないはず。パートにも遅刻申請を依頼しているはず → 実データで申請有無を精査
