## 4. 休憩・所定・実働ロジックの再設計（議論中）

### 現行コードの問題（`lib/attendance.ts`・`config/attendance.config.ts`）

- `employmentType` で分岐しているのは本来「休憩の**記録方法**」の違いなのに、「控除**ルール**」の違いとして実装されている
- `calcScheduledMinutes` は雇用形態を問わず法定休憩で所定を出す → 野木さん（拘束360分）は所定360分になるが正しくは300分
- `calcLegalBreak` の閾値判定が休憩控除前の在席時間（在席481〜540分で60分控除＝過大控除の疑い）
- 外出と法定休憩の二重控除の可能性
- `anomaly-check` のパート休憩漏れ検知が6時間超のみ
- **休憩時間控除ルールの設定が計算に反映されていない（死蔵）** — 会社設定画面に「休憩時間控除ルール」（`Setting.break1Threshold/break1Minutes/break2Threshold/break2Minutes`）があり保存もできるが、参照は `admin/settings` の画面と保存処理のみ。実際の計算（打刻・承認時の編集・申請承認・Excel・一括再計算・`lib/attendance.ts`）はすべて `config/attendance.config.ts` のハードコード `BREAK_RULES`（`calcLegalBreak`）を使う。**画面で値を変えても計算は変わらない**。当初「設定画面化が必要」と記載したのは誤りで、必要なのは既存設定を計算に接続すること（2026-09-16 ユーザー指摘で訂正）。`workSun〜workSat` と同じ「設定の死蔵」パターン

### 合意した原則

> **事実でしか変わらない値を既定値（Default）で判定しない。例外が起きたら例外に合った入力を求め、入力がなければアラートを出す。**
> **計算は実態（打刻）ベース。法定との乖離は記録を書き換えず警告で出す。**

- 昼休憩の時刻（12:00）を控除判定に**使わない**。「昼を含んだから控除」ではなく「休憩をとったから控除」
- 休憩の外出打刻は運用で合理化済み。休憩時間帯への外出打刻の例外はカバー不要

### 合意した設定モデル

- `User` に**任意**の規定休憩分数を追加。未記入なら「拘束時間 × 会社設定『休憩時間控除ルール』（既存 `Setting.break1*/break2*`）」の既定値

### 丸めスイッチの設計（合意 2026-09-29）
- **遡及しない**：スイッチの切り替えは切り替え後の打刻にだけ効く。過去月・締め済み（LOCKED）の数字は動かさない。是正は翌月から、が労務の実務。過去の払い漏れ算出は機械処理でなく実打刻から行う
- → 丸めは**現行どおり打刻時に適用して保存**する方式を維持（計算・表示時に移す案は取り下げ）。実打刻 `rawClockIn/Out` は必ず保存
- **スイッチは3つ独立**。同じ丸め処理（`applyRounding`）の中で ①→②→③ の順に評価する
  - ① 定時前打刻 → 定時扱い（既存 `roundEarlyClockIn`）。早出申請がなければ定時出勤とみなす。15分丸めとは別の考え方
  - ② 定時14分以内の早出・残業 → 定時（既存 `roundNearClockTime`）。申請しない限り定時出退勤を促す
  - ③ 全体の15分丸め（新設）。出勤は15分単位で切り上げ、退勤は切り捨て（旧勤怠Reco と同じ）。違法性は高いが実務では通る。法改正で全面禁止になった時に切れるようにするためのスイッチ
- **③ON なら②も強制 ON**（画面ではチェック済みのまま操作不可）。③の切り捨てだけで定時後14分以内の退勤も定時に丸まるため、②OFF が意味をなさない。人間にも挙動が分かりやすい
- ①と③：定時前は①が先に評価されるので矛盾なし（①OFF・③ON なら 8:10 → 8:15 のように早出を15分単位で計上）
- **③の15分区切りは本人の定時を起点に刻む**（出勤は始業時刻から、退勤は終業時刻から15分ずつ）。時計の :00/:15/:30/:45 で刻むと、定時が区切りに乗らない人で定時を越えて丸め、架空の早退・遅刻が生まれるため（例：終業17:40・17:43退勤 → 時計刻みだと17:30＝早退10分）。定時が区切りに乗っている人は時計刻みと結果が同じ。**この基準点を忘れると大きなロジックの穴になる** → DOMAIN_MAP.md の丸めの節にも記載済み、実装時はコードコメントとテスト（定時が区切り外のケース）にも残す
- **早出・残業申請がある日も③は効かせる**（①②は従来どおり無効）。例：17:30〜18:07 → 18:00 に切り捨て・残業30分

### 遅刻・早退の時間の定義（2026-09-29 確定）
- **遅刻・早退は時刻の差だけで出す**（今の `calcMetrics` と同じ考え方）。例：所定出勤 9:00・9:23 出勤 → 遅刻23分。所定退勤 15:00・14:12 退勤 → 早退48分。それ以上でもそれ以下でもない
- 一度「働いた時間の不足（所定の労働時間 − 実働）で出す」と合意したが**撤回**。不足の合計は遅刻か早退の理由を推定できるだけで、検算には使えても**新たな時数の算定基準にしてはいけない**（ユーザー指示）
- **原則3（ユーザー指示）**：それぞれの計算式はそれぞれで扱い、ある計算結果を別の新しい値の根拠にしない。計算ロジックの差で謎の数字が生まれ、謎の値ごとにカラムが必要になる
- したがって「遅刻と早退が同じ日にある場合の配分」「休憩を規定より長く取った日の不足（休憩超過）」のような新しい値は作らない。実際の勤務時間は記録に出ているので、それで困らない。管理者に計算上の注意を促すアラートは必要になるかもしれないが、管理者が入力する項目は作らない（入力すべき適切な項目がないため）
- 参考：旧勤怠Reco は 12:05 早退（所定 15:00）を「早 2:00」と出していた（昼休憩分を差し引いた値）。新システムでは時刻の差のとおり
- **【決定 2026-10-06】遅刻・早退の分数は③15分丸めの設定に連動させる**。③OFF：記録された時刻から1分単位で出す（修正していない日は実打刻と同じ値、修正した日は修正後の時刻）。③ON：15分丸めした時刻から15分単位で出す。例：9:23出勤 → ③OFF は遅刻23分／③ON は出勤9:30・遅刻30分。③OFF でも記録時刻から出すのは、遅刻・早退側は①②では丸まらない（①は定時前だけ、②は8/19以降は早出・残業側だけ）ので記録時刻＝1分単位のままだから。**実打刻から直接出してはいけない**：打刻修正した日（例：9:23 に押したのを 9:00 に修正）で修正が無視されるため。理由：実務担当者は今も丸めた後の値で計算している。実打刻から出すと、出勤時刻・勤務時間と遅刻が同じ行で合わなくなり、実打刻が無い日（代理打刻・手入力・修正申請）は丸め後から出すしかないので日によって基準が混ざる。スイッチ1つで全部が切り替わる方が分かりやすい。旧勤怠Reco（9:29 → 遅 0:30）とも一致。現行コード（`calcMetrics` が丸め後の `clockIn/clockOut` から算出）の考え方のままでよい

### 打刻時刻の決め方を1本の計算にする（2026-10-06〜07 合意。`docs/CLOCK_PIPELINE.md` にまとめる予定）
- **原則**：記録時刻は、入力（実打刻〔打刻修正で直した時刻を含む〕・承認済みの申請・その日に有効だったスイッチ・その日の定時）から、決まった順の段を通して毎回最初から出し直す。入力が変わったら（申請の承認・却下・取り消し・修正）同じ計算でやり直す。締め済みの日は除く。スイッチが全部 OFF なら記録時刻＝実打刻。経路ごとに別の直し方をしない（これまでの「重大な事実の発見」の多くは経路ごとの直し方の食い違いが原因）
- **②は申請の有無に関係なく効く**（出退勤の14分以内の端数処理）。本番は判定の不具合で実際にこう動いていた。2026-05-27 の「申請がある日は②無効」は改める（リリース2の H で入れた「判定の修正」は取り消す）
- **遅刻・早退**：時刻の差だけで出す。早退も遅刻と同じ扱い。遅刻・早退申請の時刻で記録時刻を上書きしない（申請は理由と時刻の届け出）
- **申請の確認のしかた**：
  - 事後申請（打刻の後に出す。遅刻の届け出など）は実打刻と照らし合わせ、食い違えば申請画面に戻して赤字で知らせ、受け付けない（遅刻申請なら記録より早い時刻、早退申請なら記録より遅い時刻は不可）。その場で正しい時刻で出し直してもらう。ホーム等への通知は不要
  - 事前申請（残業・早出・事前の遅刻など）は出した時点で打刻が無いのでシステムでは判定できない。実際の働き方を見ている**上長の確認を判定の一部とする**。管理者もシステムも全員の行動は見ていない。だから要確認などの**通知が必要**。申請承認の画面に打刻時刻を並べ、食い違いを目立たせる
  - 例外的な処理は一般の判定では足りないので通知を使う。**「通知は不要、誤りは全部申請画面で止める」と一律にしないこと**（ユーザー指摘）
- **早出申請がある日の出勤時刻**：実打刻に「申請できる時刻の刻み（今は15分）での切り上げ」と②③の設定に従った丸めをかけ、その時刻と申請の開始時刻の遅い方を有効な開始時刻とする。有効な開始時刻が定時以降なら早出申請は無効として、申請が無い日と同じく設定どおりに処理（ノーワーク・ノーペイ）。実打刻は実際の時刻のまま保存。例（定時 9:00・申請 8:00〜）：7:40 出勤 → 8:00／8:13 → 8:15（早出45分）／8:50 → 申請無効、①か②が ON なら 9:00、全部 OFF なら 8:50。**15分は決め打ちではない**：申請の刻み・②・③の3つから決まる。申請の刻みは設定値として1か所にまとめ、申請フォームとこの計算の両方が参照する（申請を1分刻みにして丸めを全部 OFF にすれば、申請 8:13・8:13 出勤 → 8:13）。残業の終了側も同じ刻みが効く対称な形
- **残業時間 ＝ 早出（定時の始業 − 記録した出勤）＋ 残業（記録した退勤 − 定時の終業）**。遅刻・早退と同じく時刻の差。「実働 − 所定」案は取り下げ（休憩や遅刻の分が混ざるため）。Excel の残業欄（1つ）には合計を出す。早出して早退した日は、早出（残業）と早退をそれぞれ記録し、差し引きした新しい数字は作らない（例：8:00 出勤・16:30 早退 → 早出60分・早退60分）。矛盾する数字を作らず現実に即すこと
- **早出側の打ち切り（申請の開始時刻より前は数えない）は④と同じスイッチで切り替える**（2026-10-07 決定）。④OFF なら早出も残業も申請時刻で打ち切らない。法令上の問題が出たら④だけで両側を止められる
- **「0. その日の定時を決める」段を計算の最初に置く**（2026-10-07 決定）。以降の段（遅刻・早退・早出・残業・④の打ち切り）はすべてその日の定時が基準。事実：今の遅刻・早退・要確認の判定は半休を一切見ておらず、午前半休で 13:00 出勤すると遅刻4時間・要確認になる。休日出勤も通常の定時で遅刻・早退が出る（代理打刻の休日出勤の印がある日だけ0）

  - **会社の運用は原則「振替休日」**（事前に休む日を決めてから休日出勤し、割増が発生しないようにしている。7/06 に「代休」の表示名を「振休」に変えたのもこのため）。**代休は原則使わない**（管理者の許可が必要）
  - 仕組み（案A）：休日出勤申請に「代わりに休む日」の欄を設ける。入れて申請＝振替休日、入れずに申請し後で休む日を申請＝代休（その社員の代休未取得の休日出勤を選択肢に出してひも付ける）
  - 申請画面の説明：「原則として振替休日とするため、代わりに休む日を決めて申請してください」
  - 休む日を空欄のまま送ろうとしたら確認ダイアログ：「休日を指定せずに提出すると「代休」となり、処理が変わります。原則として、管理者の許可がなければ代休は取得できません。許可を得ていない場合は、休日を選択して申請し直してください。」［このまま代休として提出する］［戻って休日を指定する］。戻る場合は入力内容を保持
  - Excel：旧様式どおり、振替休日は「振替日」の欄（5列目）、代休は「代休」の欄（27列目。7/06 に見出しを「振休」に変えたのを戻すか要整理）。足りない欄があれば拡張してよい（ユーザー了承）
- **振替で休む日を別の週にした場合**（2026-10-07 決定）：申請時に確認ダイアログ「休日出勤と別の週の日を休日にすると、時間外の割増が発生する場合があります。同じ週の中で選べないか確認してください」［このまま提出する］［戻って選び直す］。どうすべきかは上長が運用で示す。実際は割増を付けていない可能性あり
- **割増の振り分け**（2026-10-07 決定）：スイッチは持たない。残業時間の合計は変えず、Excel の既存の空欄に振り分けて出すだけ（割増を付けるかは給与計算側で判断）。残業時間（10列目）＝合計／法定内残業時間（11）＝所定超〜1日8h・週40h以内／法定外残業時間（12）＝1日8h超または週40h超（25%）／法定休日出勤（15〜18）＝法定休日の労働（35%）／休日出勤（19〜22）＝法定外の休日に振替なしで働いた時間。振替休日を別の週にした場合の週40h超は法定外残業時間に入る
  - 週40時間の判定は週全体で決まるので、日ごとに保存せず、画面・Excel に出すときに週単位で毎回計算する。週が締め期間をまたぐときは前後の期間の勤怠も読む
  - **週の起算日は日曜日（仮置き）**。就業規則の定めが不明のため。会社設定で変えられるようにする。法定休日とあわせて**ユーザーが労務担当者に確認する**
