# 打刻時刻の決め方（打刻パイプライン）

作成 2026-10-07。**打刻時刻・遅刻・早退・残業・休憩・休日出勤に触る作業は、コードを読む前に必ずこのファイルを読むこと。** ここに書かれた段の順番と規則が正であり、コードはこの番号どおりに作る。個別の経路で別の直し方をしてはいけない（これまでの不具合の多くは、経路ごとに違う直し方をしたことが原因）。

決定の経緯・理由は `docs/SESSION_2026-09-16_admin-requests.md`。

---

## 原則

1. **記録時刻は、毎回同じ計算で最初から出し直す**
   - 入力：実打刻（打刻修正で直した時刻を含む）・承認済みの申請・**その日の打刻時点のスイッチ状態（記録に保存したもの）**・その日の定時
   - 出力：記録時刻（出勤・退勤）・遅刻・早退・残業・休憩
   - 入力が変わったら（申請の承認・却下・取り消し・修正、打刻修正）、同じ関数で最初からやり直す。**締め済み（LOCKED）の日は計算し直さない**
   - スイッチが全部 OFF なら、記録時刻＝実打刻
2. **打刻時刻は3層**：実打刻 `rawClockIn/Out`（証跡。計算の入力にはなるが書き換えない）／記録時刻 `clockIn/Out`（このパイプラインの出力。集計はすべてこれ）／修正前値 `originalClockIn/Out`
3. **事実でしか変わらない値を既定値で推定しない**。例外は入力を求め、無ければ知らせる
4. **ある計算結果を別の新しい値の根拠にしない**。遅刻・早退・残業はそれぞれ時刻の差。差し引きした数字を作らない
5. **遡及しない**：スイッチ状態は打刻時点のものを記録に保存し、計算し直すときもそれを使う
6. **一般社員の画面に、④で削った内訳を出さない**（管理画面と Excel だけ）

## 段（この順に評価する）

### 段0：その日の定時を決める
- 通常の日 → 本人の定時（`workStartTime`〜`workEndTime`）
- **正社員の半休** → 昼休憩を除いた前半か後半。午前半休＝（昼休憩の終わり）〜終業、午後半休＝始業〜（昼休憩の開始）。昼休憩の終わり＝開始＋本人の休憩の長さ。例：9:00〜17:30・休憩60分 → 午前半休 13:00〜17:30、午後半休 9:00〜12:00。**パートには半休が無い**（全休のみ。部分的な休みは遅刻・早退）
- **承認済みの休日出勤申請がある日** → 申請の開始〜終了時刻を定時の代わりにする
- **休日（休日カレンダー・本人の休みの曜日）で休日出勤申請が無い日** → 定時なし。遅刻・早退は付けない。打刻があれば本人と管理者に知らせる
- **振替で労働日になった休日** → その日は通常の労働日（本人の定時）

### 段1：入力の時刻
- 実打刻。打刻修正で直した時刻があればそれを入力にする（修正した時刻にも以降の段の丸めをかける）

### 段2：早出（出勤側）
- **早出申請がある日**：有効な開始時刻 ＝ max（申請の開始時刻, 実打刻を「申請の刻み」で切り上げ→②③の設定で丸めた時刻）。④OFF なら申請の開始時刻でも申請の刻みでも区切らず、実打刻を②③で丸めた時刻だけを使う（例：申請 8:00・7:40 出勤 → 7:40。2026-10-07 決定。予定より早く出勤した分は法令上支払いが必要なため、実打刻を使うほかない。「予定時刻まで打刻しない」運用で補う）
  - 有効な開始時刻が定時以降になれば早出申請は無効として、申請が無い日と同じ扱い
  - 例（定時 9:00・申請 8:00・④ON）：7:40 → 8:00／8:13 → 8:15／8:50 → 申請無効 → 段3以降の通常処理（①か②が ON なら 9:00、全部 OFF なら 8:50）
- **申請が無い日**：①ON か④ON なら定時前の出勤は定時（④ON なら①も効く。③ON なら②も効くのと同じ形。2026-10-07 決定）

### 段3：②の端数処理
- 定時から14分以内の早出・残業側の端数を定時に（出勤は定時前14分以内、退勤は定時後14分以内）。遅刻・早退側は丸めない。申請の有無に関係なく効く

### 段4：遅刻・早退
- 出勤が定時より遅ければ遅刻、退勤が定時より早ければ早退。**時刻の差だけで出す**
- 遅刻・早退申請の時刻で記録時刻を上書きしない（申請は理由と時刻の届け出）
- ③ON なら丸めた記録時刻から出すので15分単位、OFF なら1分単位

### 段5：③の15分丸め
- 出勤は切り上げ、退勤は切り捨て。区切りはその日の定時が起点（定時が区切りから外れる人でも、定時をまたいで丸めない）
- 早出・残業申請がある日も効く

### 段6：④の打ち切り
- 退勤の記録時刻 ＝ min（段5までの退勤, 上限）
  - 上限 ＝ 承認済みの残業申請（早出申請は除く）のうち**最後に出した申請**の終了時刻。無ければ定時
- 出勤側は段2で処理済み（申請が無い日も、④ON なら定時で打ち切る）
- 上限が出勤より前になる場合（定時後に出勤し、申請なしで働いた日など）は勤務0分。注意表示の対象。遅刻は時刻の差のとおり出す（例：定時 9:00 で 18:00 出勤 → 遅刻540。2026-10-07 決定）
- 実打刻は書き換えない

### 段6.5：管理者の確定修正（最優先。2026-10-07 決定）
- 管理者の直接修正と代理打刻で入れた時刻は、段0〜6の結果を**最後に上書き**する（丸め・④を通さない）。遅刻・早退・休憩・残業は上書きした後の時刻から計算する
- 保存は実打刻・記録時刻とは別の場所。実打刻は書き換えない。後で申請が承認されて計算し直しても、管理者の修正が残り最後に勝つ。変更履歴は残す
- **取り消し**（2026-10-07 決定）：承認詳細の「管理者の修正を取り消す」で、直した項目だけを1つ前に戻す
  - 1つ前が管理者の修正・代理打刻なら、その時刻に戻す（管理者の入力として残し、丸めない）。例：代理打刻 8:50〜17:30 → 出勤を 9:10 に修正 → 取り消し → 出勤 8:50、退勤 17:30 のまま
  - 1つ前が承認済みの打刻修正なら、その修正時刻を段1の入力に戻す（丸める）。何も無ければ実打刻に戻す
  - 承認済みの打刻修正申請を削除したときも同じ考え方で、修正前に戻して計算し直す。同じ項目の修正を全部削除すれば実打刻（実打刻が無ければ空）に戻る
  - 変更履歴は消さずに追記する。取り消しの履歴は `revertsLogId` で取り消した履歴を指し、取り消された履歴は戻し先として数えない
  - Excel の「変更出勤・変更退勤」欄は、取り消した結果、実打刻と同じに戻った日は「-」
  - 締め済み（LOCKED）の日は取り消し・削除ともエラーで止める。取り消す履歴を特定できない日はボタンを出さない
- **リリース2より前の管理者修正・代理打刻**：デプロイ時の migration（20261007000000）で1回だけ、変更履歴から admin 列へ移す。7/6 より前の承認は承認の記録が無いため、人・日・項目・時刻の一致で申請由来を見分ける
- **入力画面はスイッチに従った選択肢を基本にする**：スイッチの結果としてあり得る時刻だけを選べる（例：③ON なら15分刻み、④ON なら退勤は上限まで）。考え方としては「その時刻をパイプラインに通しても変わらない時刻」だけを選択肢に出す
- 管理者が必要と判断したときだけ「制限なしで入力する」チェックを入れると、1分単位・全時間帯から選べる（残業・早出申請フォームの「すべての時間を表示」と同じ考え方）
- 打刻修正申請（本人が申請し上長が承認）は対象外。段1の入力として扱い、スイッチに従って丸める

### 段7：休憩
- 休憩分数の決め方（上から順に）
  1. その日の `breakMinutes` に値がある（パートの休憩ボタン、承認済みの休憩申請・早退申請の休憩の申告・休日出勤申請の休憩）→ その値（0を含む）
  2. 過去の休憩打刻（休憩開始・終了）がある → その差（正社員も。旧計算が打刻を見ていなかった誤りの修正。2026-10-07 了承）
  3. パート → 0（下の申請漏れアラートの対象になりうる）
  4. 休日で休日出勤申請が承認されていない日（定時なし）の正社員 → 在席時間（外出を除く）に法定休憩（6時間超45分・8時間超60分）。本人の所定休憩は使わない（**休日出勤の場合は勤務時間も休憩も上長の承認で初めて有効**。平日には広げない）
  5. 半休の日 → ⑤ON は0、⑤OFF は在席時間に法定休憩（旧方式）
  6. 正社員 → ⑤ON：規定値＝本人の `User.breakMinutes`、無ければ会社設定の休憩時間控除ルール（`Setting.break1*/break2*`）を**定時の拘束時間**に当てた値／⑤OFF：在席時間に法定休憩（旧方式）
- 審査中の休憩申請・申告は差し引かない
- 休憩の申告（休憩申請・早退申請・休日出勤申請）は、承認した順につながった1本の流れとして扱う。削除・修正・日付の移動では、その申告の直前の値に戻す（途中の申告を消したときは記録を変えずつながりから抜く）。承認済みの申告がある日はパートの休憩ボタンを断る
- **早退した日の休憩**（2026-10-07 決定）：退勤時刻（例 14:00）からは休憩を取ったか機械的に判別できないため、正社員の早退申請に「休憩を取りましたか」（取らなかった／取った→15分刻み）を必須で入れる。定時前に退勤したら退勤直後の画面とホームで早退申請を促す（休日出勤の日は出さない）。運用として「早退したらその日のうちに申請」を周知。申請が無い日は規定値
- 休憩の時間帯で控除を判定しない（「昼を含んだから控除」ではなく「休憩を取ったから控除」）

### 段8：残業
- **残業 ＝ 早出（定時の始業 − 記録した出勤）＋ 残業（記録した退勤 − 定時の終業）**。どちらも0未満は0（⑤ON。⑤OFF は旧方式の「実働 − 所定」。旧コードは退勤時と承認時で基準が違ったため、承認時の式にそろえた）
- 早出して早退した日は、早出（残業）と早退をそれぞれ出す。差し引きしない
- Excel の振り分け（スイッチなし。合計は変えず、画面・Excel に出すときに週単位で毎回計算）：残業時間＝合計／法定内残業＝所定超〜1日8h・週40h以内／法定外残業＝1日8h超か週40h超／法定休日出勤＝法定休日の労働／休日出勤＝法定外の休日に振替なしで働いた時間。週が締め期間をまたぐときは前後の期間も読む

## 申請の確認のしかた

- **事後申請**（打刻の後に出す。遅刻の届け出など）：実打刻と照らし合わせ、食い違えば申請画面に戻して赤字で知らせ、受け付けない。その場で出し直してもらう
- **事前申請**（残業・早出・休日出勤・事前の遅刻など）：出した時点では打刻が無く、システムでは判定できない。**上長の確認を判定の一部とする**ので、要確認などの通知が必要。申請承認の画面に打刻時刻を並べ、食い違いを目立たせる
- 例外的な処理：一般の判定では足りないので通知を使う
- **「通知は不要、誤りは全部申請画面で止める」と一律にしないこと**

## 休日出勤・振休・代休

- 申請は「**休日出勤申請**」1つ。休日出勤する予定日・予定の開始〜終了時刻（初期値は本人の所定の定時）・代わりに休む日を入れる
- **振休か代休かはシステムが決める**：休日出勤申請と一緒に休む日を決めた＝振休／後で決めた＝代休。休む日が休日出勤の前でも後でもよい（区別は「いつ決めたか」）
- 会社の原則は振休。休む日を空欄で送ろうとしたら確認ダイアログ（代休は管理者の許可が要る旨）。休む日が休日出勤と別の週なら、時間外の割増の可能性を知らせる確認ダイアログ
- 代休の残り時間は管理しない。代休は休日出勤1件にひも付ける
- 過去の「振休」データはそのまま残す。Excel：振休は「振替日」欄、代休は「代休」欄
- 旧「振休申請」は新規申請フォームから外した（サーバーでも新規作成を断る）。過去データの表示・管理者の修正は残す
- 休む日は休日出勤1件につき1日。ほかの申請（審査中・承認済み）で指定済みの日は選べない
- 休む日の行には Excel・/records・承認詳細で「振休（10/12 出勤分）」「代休（10/12 出勤分）」と出し、欠勤と見分ける
- 休日出勤申請には「休憩（分）」を必須で入れ、承認されたら休憩分数に反映
- 承認された休日出勤の日には休日出勤の印 `isHolidayWork` を自動で付ける（代理打刻のチェックと同じ印）。印の出どころ（代理打刻か申請か）は `holidayWorkByProxy` で分け、申請の削除では申請由来の印だけ外す。代理の印は管理者の編集の「休日出勤（代理）」で付け外しする

## 知らせる・目印を出す条件

- 残業申請が無いのに、実打刻が定時を15分以上過ぎた日（④ON のときだけ）：本人には退勤直後と当日のホームで注意を促す程度（翌日以降は出さない・要確認に入れない・削った時間は出さない）、管理者には勤務状況一覧と承認詳細に控えめな目印
- 休日に、休日出勤申請が無いまま打刻があった日：同上
- パートの休憩申請漏れ：所定休憩が設定されているのに休憩の記録が無い日／実働6時間超で休憩の記録が無い日
- 一般社員の勤怠記録の画面：④で打ち切った退勤には実打刻を併記しない（①〜③の丸めの差は従来どおり併記）
